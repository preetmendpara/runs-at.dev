# runs-at.dev self-hosted DNS (PowerDNS on OCI Always Free)

**Status: NOT APPLIED.** None of this has been provisioned. No `tofu plan` or
`tofu apply` has been run, no instance exists, and no glue IPs exist. The
machine this was written on has no OCI credentials, OCI CLI, OpenTofu or SSH
keys. Production cutover is also blocked by the registrar: runs-at.dev is at
Cloudflare Registrar, which does not allow custom nameservers, so the domain
must be transferred to another registrar before ns1/ns2 can be delegated.

## Layout

| Path | What |
| --- | --- |
| `opentofu/` | VCN, subnet, security list (UDP+TCP 53 from anywhere, SSH 22 from `ssh_allowed_cidr` only), two Always Free instances `ns1`/`ns2`, reserved public IPs |
| `powerdns/` | `pdns.conf` for primary (gpgsql on loopback PostgreSQL) and secondary (gsqlite3), systemd hardening drop-in, first-boot setup, nightly backup, cron, logrotate, unattended-upgrades |
| `cloud-init/` | `ns1.yaml`/`ns2.yaml`, generated by `node infra/cloud-init/build.mjs` from `powerdns/` and `monitoring/` (a test fails if they drift) |
| `monitoring/check-dns.sh` | SOA serial compare ns1 vs ns2, UDP and TCP |

Private addresses are fixed: ns1 `10.53.1.11`, ns2 `10.53.1.12`. Zone
transfers and NOTIFY go over the VCN, TSIG-signed.

## Cost guard

Only `VM.Standard.E2.1.Micro` (default) or `VM.Standard.A1.Flex` (validated to
at most 2 OCPU / 12 GB each, 4 / 24 total) are accepted, boot volumes are
50 GB each (200 GB free). Before applying, confirm in the OCI console that the
tenancy is on Always Free limits and that reserved public IPs are free in your
tenancy; budgets and limits differ per account and were not checkable here.

## Runbook (when credentials exist)

1. `cd infra/opentofu && cp terraform.tfvars.example terraform.tfvars`, fill it, `tofu init && tofu plan`. Review, then `tofu apply`. Note the `glue` output.
2. `NS1_IPV4=<ns1> NS2_IPV4=<ns2> node scripts/export-zone.mjs`, then `node scripts/verify-parity.mjs` (must exit 0). Copy `migration/zone/runs-at.dev.zone` to ns1 and `pdnsutil load-zone runs-at.dev runs-at.dev.zone` (on a re-load, `pdnsutil increase-serial`).
3. On ns1: `pdnsutil list-tsig-keys` and `pdnsutil set-meta runs-at.dev TSIG-ALLOW-AXFR xfr-runs-at-dev`. On ns2: `pdnsutil import-tsig-key xfr-runs-at-dev hmac-sha256 '<secret>'` (paste over SSH; never commit it), then rerun `/usr/local/sbin/setup-pdns.sh`.
4. Check: `NS1=<ns1> NS2=<ns2> infra/monitoring/check-dns.sh` and `node scripts/verify-parity.mjs --server <ns1>` then `--server <ns2>`.
5. Only after the domain is at a registrar that allows custom nameservers: register host objects ns1/ns2.runs-at.dev with the glue IPs, then change the delegation. Keep Cloudflare serving until the old NS TTL has expired everywhere.

## Known gaps

- The wildcard today is a proxied Cloudflare record answered by `cloudflare/worker.js`. The export copies the Cloudflare edge IPs that answer now; those stop working once the zone leaves Cloudflare. Set `WILDCARD_CNAME` for the exporter once a non-Cloudflare host for the profile card exists.
- Apex MX/SPF point at Cloudflare Email Routing, which also requires the zone on Cloudflare.
- DNSSEC is not set up (today's delegation is unsigned too).
- Both hosts share the same unattended-upgrades reboot policy; stagger `Unattended-Upgrade::Automatic-Reboot-Time` per host if simultaneous reboots matter.
- `sync-dns.mjs` still writes to Cloudflare; a PowerDNS provider (API via SSH tunnel to 127.0.0.1:8081) is separate work.
